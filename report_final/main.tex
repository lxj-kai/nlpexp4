\begin{abstract}
本项目研究 RAG 检索文档噪音对大模型问答的影响，并系统比较噪音修复方法。报告以\textbf{数据集为主线}组织实验：RGB、2Wiki、Cmedqa、MIRIAD、MobileMem、BRIGHT、TEMPO、MultiHop-RAG 与 NoiserBench 均转换为统一的 \texttt{RGBRecord} 格式，在相同噪音注入协议下分别报告数据集特点、噪音类型、矫正方法、实验结果和代表性样例。项目实现 semantic、counterfactual、mixed 及 NoiserBench 细粒度噪音，比较 naive、prompt、iterative、confidence（CoT 证据链）、selfrag、voting、adaptive 等方法。总体发现是：语义噪音下 confidence 通常能通过逐篇证据匹配恢复答案，反事实噪音下 prompt/adaptive 更稳；不同数据集的绝对分数不可混比，但“噪音类型决定最优修复策略”的规律在多数据集上反复出现。
\end{abstract}

\section{课题背景}

\subsection{课题目标}
本项目对应 NLP 实验四题目 8：\textbf{面向大模型 RAG 推理场景噪音文档的鲁棒性推理方法}。题目要求关注大模型 RAG 场景中，检索结果可能包含与问题语义相关、但缺少逻辑依赖或会误导答案的上下文文档，进而影响模型问答准确率。项目需要完成以下任务：

\begin{itemize}
  \item 探究上下文文档对模型问答性能的影响；
  \item 提出可量化的评估指标；
  \item 针对具体数据集给出实验结果、结论与分析；
  \item 结合具体案例分析不同文档对答案的影响；
  \item 设计矫正机制，例如提示词优化、迭代式生成等；
  \item 与现有方法进行性能比较，说明方法有效性与局限。
\end{itemize}

\subsection{核心问题}
本项目将问题形式化为：给定问题 $q$、候选文档集合 $D=\{d_1,\dots,d_n\}$ 和参考答案 $a$，当 $D$ 中混入不同类型、比例和位置的噪音文档时，大模型生成答案 $\hat{a}$ 的准确率、证据来源和噪音采纳程度如何变化？此外，不同的矫正机制在不同噪音类型下表现如何？是否存在“互锁效应”——即最优方法取决于噪音类型。


\subsection{成果应用价值}
\begin{itemize}
  \item \textbf{企业/医疗/法律 RAG}：可控噪音压测 NS/CRR，评估 distractor 风险；
  \item \textbf{自适应路由}：semantic 噪音优先使用 confidence（CoT 证据链），counterfactual 噪音优先使用 prompt/adaptive；
  \item \textbf{教学演示}：Web 四阶段界面展示注入噪音与矫正对比；
  \item \textbf{评测协议}：统一数据格式与多域 benchmark，覆盖 RGB、2Wiki、Cmedqa、MobileMem 等。
\end{itemize}

\subsection{主要结论预览}
经过完整的系统实现和多数据集实验验证，本项目核心发现包括：

\begin{itemize}
  \item \textbf{数据集差异显著}：RGB 抗噪最强，2Wiki、Cmedqa 和 MIRIAD 改用 DeepSeek Judge 观察语义正确性，MobileMem 与 BRIGHT 同样使用 Judge 口径；
  \item \textbf{噪音类型决定修复策略}：semantic 噪音下 confidence（CoT 证据链，方法 C）通常最有效；counterfactual 噪音下 confidence 可能强化假证据，prompt/adaptive 更稳；
  \item \textbf{高强度噪音暴露模型边界}：当 positive 文档被大量挤出甚至完全消失时，naive 出现断崖式下降，任何修复方法都难以恢复不存在的证据；
  \item \textbf{位置效应}：在 r=0.75 反事实噪音下，文档放末尾（back）的破坏力最大（F1=0.629），印证 recency bias 在错误信息场景下的危害；
  \item \textbf{样例层面可解释}：RGB、MobileMem、BRIGHT 等样例显示，修复成功通常来自“识别问题约束→定位 positive 证据→抑制同主题噪音”。
\end{itemize}

\subsection{调用流水线}
单次实验的主流程如下：

\begin{enumerate}
  \item \textbf{加载数据}：读取指定数据集、语言和子集的 \texttt{RGBRecord} 样本；

  \item \textbf{调用模型}：按实验口径访问 DeepSeek API 或本地 qwen3-4b，使用 sha1 缓存减少重复调用；
  \item \textbf{计算指标}：输出基础问答指标与鲁棒性指标；
  \item \textbf{落盘与可视化}：保存 JSON，生成图表，并同步报告与前端展示。
\end{enumerate}

\section{方法主要技术}

\subsection{噪音注入机制}
设最大上下文文档数为 $K$，目标噪音比例为 $r$。系统从 \texttt{positive} 中采样 $K(1-r)$ 个有效文档，从噪音池中采样 $Kr$ 个噪音文档。噪音类型包括：

\begin{itemize}
  \item \textbf{semantic}：从 \texttt{negative} 中采样普通语义噪音；
  \item \textbf{counterfactual}：从 \texttt{positive\_wrong} 中采样反事实噪音；
  \item \textbf{mixed}：同时混合普通噪音和反事实噪音。
\end{itemize}

噪音位置包括 front、back、interleave、surround，用于观察上下文位置偏见对回答的影响。

\paragraph{适用前提。} \textbf{semantic} 仅从 \texttt{negative} 采样，凡具备语义负例池的数据集均可使用。\textbf{counterfactual} 与 \textbf{mixed} 依赖 \texttt{positive\_wrong}：若样本缺少该字段，\texttt{noise\_injector.py} 将直接报错。因此三类噪音\textbf{并非}在所有数据集的主实验中全量运行——跨数据集主表以 semantic 为主；counterfactual / mixed 的系统对比集中在 RGB fact、2Wiki fact 与 NoiserBench 等具备原生或可构造反事实字段的子集上。各数据集 \texttt{positive\_wrong} 的来源见表~\ref{tab:counterfactual_construction}。

\subsection{深化方法详解}

\textbf{方向 1：自适应矫正器 (Adaptive Corrector)。} 首先用 1 次 API 调用快速扫描文档，检测是否存在明显矛盾/反事实陈述。若检测到 CF（反事实），路由到 PromptCorrector；若检测为 CLEAN，路由到 ConfidenceCorrector（CoT 证据链）；若不确定，路由到 VotingCorrector 稳健兜底。总 API 调用 2--4 次。

\textbf{方向 2：语义级 ISR/NAR。} 将字符级 token 重叠升级为 LLM 驱动的句子级信息归属判定。每个答案拆分为最小信息单元，LLM 逐条标注来源文档、可信度，并检测幻觉内容。

\textbf{方向 3：Confidence 消融实验。} 创建 4 个变体：C\_full（完整四步）、C\_no\_decompose（去掉拆解信息需求）、C\_no\_evidence（去掉逐篇证据匹配——最关键的消融）、C\_no\_tag（去掉 \texttt{<answer>} 标签约束）。用于验证哪一步是 CoT 证据链的核心。

\textbf{方向 4：迭代自纠正循环。} Round 0 初答 → Round 1 自检矛盾+标记可疑文档+修订 → Round 2 再自检+再修订 → 最多 3 轮或收敛则停。每轮记录 ISR/NAR 变化。




\subsection{核心 Prompt 与代码说明}
\textbf{CoT 证据链（confidence，\texttt{src/prompts.py}）：} Step1 拆解信息需求；Step2 逐篇标注 \texttt{Doc[i]->信息点}；Step3 仅基于证据综合；Step4 输出 \texttt{<answer>}。

\textbf{Prompt-aware（prompt）：} 要求识别每篇文档是否真正有用，只基于有用文档作答，发现矛盾需标注来源。

\textbf{核心代码：} \texttt{noise\_injector.py}（$K(1-r)$ positive + $Kr$ 噪音采样）；\texttt{llm\_client.py}（LM Studio 调用、token 预算截断、sha1 缓存）；\texttt{rag\_pipeline.py} + \texttt{correctors/}（12 种矫正器）；\texttt{evaluator.py}（DeepSeek Judge）；\texttt{experiments/\_runner.py}（条件矩阵、checkpoint）。

\subsection{基础问答指标}

\begin{itemize}
  \item \metric{EM}：规范化后完全匹配；
  \item \metric{Contains}：参考答案是否被预测答案包含；
  \item \metric{Token-F1}：token 级精确率与召回率调和平均；
  \item \metric{ROUGE-L}：基于最长公共子序列的 F1；
\end{itemize}

\section{实验情况}

\subsection{实验设置与模型配置}

主实验按\textbf{数据集}组织。每个数据集先说明语料特点和可构造的噪音类型，再报告相同协议下的噪音影响与矫正结果。所有数据统一为 \texttt{RGBRecord}：
\[
  (query,\ answer,\ positive,\ negative,\ positive\_wrong)
\]
其中 \texttt{positive} 表示支持答案的证据，\texttt{negative} 表示语义相关但不支持答案的普通噪音，反事实字段表示表面相关但导向错误答案的噪音。三类噪音并非在所有数据集上全量运行；各数据集覆盖范围与 \texttt{positive\_wrong} 构造方式详见第~\ref{sec:noise_coverage} 节及表~\ref{tab:noise_coverage}、表~\ref{tab:counterfactual_construction}。

\subsection{矫正方法口径}

后续所有表格中，方法名称保持一致：
\begin{itemize}
  \item \textbf{naive}：不做噪音识别，直接拼接文档作答，是所有数据集的基线；
  \item \textbf{prompt}：在提示词中显式要求识别噪音、标注来源并指出矛盾，主要用于 counterfactual 场景；
  \item \textbf{iterative}：逐文档评分后过滤再生成，成本较高，主要用于 RGB/2Wiki 对比；
  \item \textbf{confidence}：方法 C，即 CoT 证据链，通过“拆解需求→逐篇证据匹配→综合→输出”完成修复；
  \item \textbf{selfrag}：简化 Self-RAG 对比基线；
  \item \textbf{voting}：多 Persona 独立推理后投票或聚合，通常作为稳健候选；
  \item \textbf{adaptive}：先检测是否存在反事实/矛盾，再路由到 prompt、confidence 或 voting；
  \item \textbf{ablated\_*}：confidence 的消融变体，用于分析 CoT 证据链中哪一步有效，不计作独立主方法。
\end{itemize}

\subsection{MobileMem：自建私人记忆 RAG Benchmark}
\label{sec:mobilemem}

\textbf{为何需要 MobileMem。} 现有公开 RAG 基准（RGB、2Wiki、BRIGHT 等）检索的多为百科或新闻等\textbf{世界知识}：模型往往可凭预训练参数记忆直接作答，或在未真正阅读上下文时仍给出 plausible 答案。这会引入 RAG 噪音研究中的\textbf{「检索不必要」混淆}——性能变化究竟来自 distractor 文档的干扰，还是来自模型本就不依赖检索？若无法区分二者，则 semantic 噪音比例、矫正方法收益等指标都会被高估或误判。MobileMem 针对该缺口\textbf{自建}：问题答案绑定于虚拟用户的私人生活细节（具体购物金额、转账流水、OCR 截图文字等），这些信息不在公开预训练语料中，\textbf{闭卷无法作答、必须依赖检索上下文}，从而保证噪音实验测的是「给定必须检索的前提下，混入相关 distractor 后模型能否仍定位正确证据」。

\textbf{数据构造。} 我们构造虚拟用户「赵云澈」2025 全年（Q1--Q4）的生活记忆图谱，包含购物截图、转账记录、群聊、朋友圈、视频/读书/音乐截图等 82 条结构化事件；每条事件含事件 ID、发生时间、长期主题标签与 OCR 字段。在此基础上生成 240 条 QA（120 calc + 120 noncalc），每条样本固定 4 条 positive；negative 为同一用户其他真实记忆，构成高相似度的 semantic 噪音——比普通百科 hard negative 更贴近个人助手场景（同季度购物、转账、聊天记录易分散注意力）。

\begin{itemize}
  \item \texttt{calc}：问题指定若干事件，要求跨事件聚合计算，例如求总价、最大最小差或计数；答案无法由常识推断，必须对齐多条 positive 记忆；
  \item \texttt{noncalc}：从指定时间窗口或指定事件集合中检索单一事实；同样依赖 OCR 字段中的私有数值或文本。
\end{itemize}

\section{实验结果和结论}

\subsection{RGB：基础噪音机制与方法互锁}

\paragraph{选用原因。} RGB 是本项目\textbf{机制分析的主基准}，选择它有三方面理由：其一，RGB 是目前少有的同时提供 \texttt{positive}、\texttt{negative} 与人工标注 \texttt{positive\_wrong} 的公开 RAG 数据集，可在同一框架下原汁原味地运行 semantic、counterfactual、mixed 三种噪音，无需启发式构造，从而为「噪音类型决定最优方法」的互锁效应提供最干净的对照；其二，RGB 同时提供中英文 main/fact/int/refine 多个子集，可同时承载跨语言、位置效应、噪音比例梯度等多组机制实验，单数据集即可覆盖实验一与实验二的主要研究问题；其三，RGB 答案较短、有明确金标，适合用 Token-F1 作主指标，便于与后续数据集的相对趋势互证。

RGB 包含中文/英文 main 子集与 fact 子集。main 子集用于 semantic 噪音，即从 \texttt{negative} 中注入相关但不支持答案的文档；fact 子集包含 \texttt{positive\_wrong}，可单独构造 counterfactual 和 mixed 噪音。RGB 承担噪音类型、位置效应、跨语言和方法互锁分析的公开基准作用。

2Wiki 是英文多跳 Wikipedia 数据集，问题通常需要组合两个以上实体关系。其 negative 多为同 context hard negative，语义相关度较高。main 子集使用 semantic 噪音；fact 子集由脚本从 hard negative 自动构造 \texttt{positive\_wrong}，用于观察 counterfactual 断崖，但质量弱于 RGB 原生 fact。

\subsection{MobileMem：私人记忆与 OCR 噪音}

\paragraph{选用原因。} MobileMem 是本项目\textbf{自建的私人记忆 RAG benchmark}，用以填补公开数据集的共同缺口——「检索不必要」混淆。RGB、2Wiki、BRIGHT 等检索的多为百科或新闻等世界知识，模型可凭预训练参数直接作答，噪音实验测的是「不依赖检索时 distractor 的影响」，而非「必须检索时 distractor 的影响」。MobileMem 把答案绑定到虚拟用户的私有生活细节（购物金额、转账流水、OCR 截图文字等），闭卷无法作答，从而保证 semantic 噪音下的性能下降可干净归因于 distractor 干扰而非参数记忆捷径。此外，MobileMem 的 calc/noncalc 双子集可同时检验「跨事件聚合计算」与「单事实检索」两种任务形态下最优方法是否不同，这正是后文 noncalc 上 prompt/voting 反超 confidence 这一关键发现的来源。

MobileMem 在本项目中的角色是\textbf{控制「检索必要性」}：问题答案绑定虚拟用户私有记忆，模型不能凭预训练知识绕过检索；因此 semantic 噪音下的 Judge Score 变化更能反映 distractor 对证据定位的真实影响。positive 与 negative 均来自同一用户记忆图谱；calc 子集要求跨事件计算，noncalc 子集要求检索单一事实。

\subsection{BRIGHT：长文 Hard Negative}

\paragraph{选用原因。} BRIGHT 被选作\textbf{长文 hard negative}的代表数据集，用来检验 RGB 等短文数据集上的结论能否迁移到「文档极长、hard negative 与问题高度相关」的复杂场景。BRIGHT 覆盖经济学、生物等 12 个子域，文档长度远超 RGB，许多答案是长文本机制归纳而非可抽取短答案，因此字面匹配指标失效，改用 Judge Score 作主指标。选择 BRIGHT 的另一原因是其 hard negative 的相似度极高（同领域、同主题但论证方向不同），可压力测试 confidence 在「positive 被海量相关噪音淹没」时是否仍能逐篇定位真正的论据。

\subsection{NoiserBench-HotpotQA：细粒度噪音类型}

\paragraph{选用原因。} NoiserBench 被选作\textbf{细粒度噪音类型的预标注基准}，弥补 RGB 三类噪音（semantic/counterfactual/mixed）粒度仍较粗的不足。它提供 semantic、supportive、orthographic、datatype、illegal\_sentence、counterfactual、counterfactual\_answer 七类预标注噪音，可检验方法是否只在「语义相关 vs 反事实」二分下成立，还是对不同机制（拼写扰动、数据类型错误、非法句子、反事实答案）有不同适配。选择 NoiserBench 的核心目的是把「噪音类型决定最优方法」的互锁效应从 3 类细化到 7 类，验证 prompt 在反事实类噪音下优于 confidence 的规律是否在更细粒度上仍然成立。

NoiserBench 提供预标注噪音，比 RGB 的 semantic/counterfactual/mixed 更细。HotpotQA 子集用于测试方法是否能区分不同噪音机制。本实验在 clean 与 $r=0.75$ 条件下比较 semantic、supportive、orthographic、datatype、illegal\_sentence、counterfactual 和 counterfactual\_answer 等类型，主指标为 Judge Score。

\subsection{统一噪音修复规律}

\begin{enumerate}
  \item \textbf{semantic 噪音的修复关键是证据定位。} RGB、2Wiki、Cmedqa、MobileMem calc、BRIGHT、TEMPO、MultiHop-RAG 都显示：当正确证据仍在上下文中，只是被相关噪音稀释时，confidence 通常能通过逐篇证据匹配恢复性能。
  \item \textbf{counterfactual 噪音的修复关键是矛盾识别。} RGB fact 与 NoiserBench 显示，反事实噪音通常是“有说服力的错误文档”。此时 prompt/adaptive 更适合，confidence 可能把假证据组织成更完整的错误推理。
  \item \textbf{任务类型会改变最优方法。} MobileMem calc 需要多事件计算，confidence 更好；MobileMem noncalc 是单事实检索，prompt/voting 更好；MIRIAD 长英文医学答案用 DeepSeek Judge 观察语义质量时，confidence 有小幅恢复。
  \item \textbf{指标必须按数据集解释。} RGB 等短答案机制实验保留字面匹配指标；2Wiki、Cmedqa、MIRIAD 以及 BRIGHT、MobileMem、TEMPO 等长文或开放答案实验使用 DeepSeek Judge / Judge Score。报告只比较同一数据集同一指标内的方法排名，不把不同指标的绝对数值直接混比。
\end{enumerate}

\subsection{实验结论}

主实验覆盖 RGB、2Wiki、Cmedqa、MIRIAD、MobileMem、BRIGHT、TEMPO、MultiHop-RAG 与 NoiserBench。不同数据集有不同任务形态和指标口径，但噪音修复规律保持一致：semantic 噪音主要考验证据定位，confidence（CoT 证据链）在多数数据集上有效；counterfactual 噪音主要考验矛盾识别，prompt/adaptive 更稳；长答案、个人记忆和论坛文本需要结合 Judge 与样例解释。实际 RAG 系统可采用 adaptive 路由：先判断是否存在反事实/矛盾，若有则走 prompt，若主要是普通相关噪音则走 confidence，若不确定则使用 voting 兜底。

\subsection{「噪音上升反而答对」现象的统一解释}
\label{sec:noise_up_acc_up}

汇总全部 128 个结果 JSON 后，共出现 33 处「含噪条件得分高于 clean」的样本（即 $S_{\text{noisy}} > S_{\text{clean}}$），分布在 RGB zh/main、RGB zh/fact、Cmedqa、MIRIAD 与 MobileMem noncalc 等数据集上。最典型的几例包括：MobileMem noncalc 上 prompt 在 $r=0.75$ 时 Judge=0.801，远高于 clean 的 0.673（相对提升 19.1\%）；MIRIAD 上 confidence 的 Token-F1 在 $r=0.75$ 时为 0.207，高于 clean 的 0.183（+13.1\%）；Cmedqa 上 confidence 在 $r=0.5$ 时 Judge=0.636，高于 clean 的 0.606（+5.0\%）；RGB zh/fact 上 mixed 噪音 $r=0.25$ 时 F1=0.915，高于 clean 的 0.895（+2.2\%）。该现象并非测量错误，而是多机制叠加的结果，下面按成因分类统一解释。

\begin{table}[H]
  \centering
  \caption{「噪音上升反而答对」的代表样本与归因}
  \label{tab:noise_up_acc_up}
  \small
  \begin{tabularx}{\textwidth}{lcccl}
    \toprule
    数据集/方法 & $S_{\text{clean}}$ & 噪音条件 & $S_{\text{noisy}}$ & 主要成因 \\
    \midrule
    MobileMem noncalc / prompt & 0.673 & semantic $r=0.75$ & 0.801 & 强约束提示+上下文增广 \\
    MobileMem noncalc / voting & 0.760 & semantic $r=0.75$ & 0.801 & 多 Persona 投票+证据对照 \\
    MIRIAD / confidence (F1) & 0.183 & semantic $r=0.75$ & 0.207 & 字面指标失真+同义改写 \\
    Cmedqa / confidence & 0.606 & semantic $r=0.5$ & 0.636 & 证据链触发+小样本波动 \\
    RGB zh/fact / naive (mixed) & 0.895 & mixed $r=0.25$ & 0.915 & 上下文增广+低比例噪音 \\
    RGB zh/main / naive & 0.712 & semantic $r=0.5$ & 0.714 & 小样本波动（$n=50$） \\
    \bottomrule
  \end{tabularx}
\end{table}

\paragraph{成因 1：强约束提示与多 Persona 投票在「证据对照」下受益。}
MobileMem noncalc 上 prompt 在 clean 时仅 0.673，但在 $r=0.75$ 时升到 0.801。原因是 noncalc 是单事实检索，prompt 提示词的核心要求是「只回答被问题限定的事实、忽略无关记忆」；当上下文中只有 positive 时，模型缺乏对照样本，容易把同主题相近记忆混入答案；而注入同用户、同主题但不支持答案的 negative 后，positive 与 negative 形成\textbf{显式对照}，prompt 要求的「识别并压制无关」机制才被真正激活，反而收窄了答案范围。voting 同理：多 Persona 在含噪时通过投票剔除跑题答案，比 clean 时一致性偏差更小。这说明\textbf{噪音在某些任务下不是纯干扰，而是激活矫正机制的「对照样本」}。

\paragraph{成因 2：字面指标对长答案同义改写失真。}
MIRIAD 的参考答案长、可接受表述多样，Token-F1 对同义改写高度敏感。clean 时模型自由组织语言，字面重合低（F1=0.183）；注入 semantic 噪音后，confidence 的逐篇证据匹配会引导模型复述文档原句作为证据，反而提高了与参考答案的 token 重合（F1=0.207）。同一条件下 DeepSeek Judge 的恢复幅度小得多（0.548 $\rightarrow$ 0.571），说明真正的语义提升有限，「上升」更多是指标口径问题。这印证了报告反复强调的\textbf{指标必须按数据集解释}：长生成任务不应单独用 Token-F1 下结论。

\paragraph{成因 3：低比例噪音的「上下文增广」效应。}
RGB zh/fact 在 $r=0.25$ 时 mixed 和 semantic 的 F1 分别为 0.915 和 0.909，均高于 clean 的 0.895。低比例噪音在保持 positive 充足的同时增加了同主题背景文档，相当于\textbf{无害的上下文增广}：模型在更多相关表述中更容易定位正确答案，类似 in-context examples 的副作用增益。NoiserBench 论文（\texttt{arXiv:2408.13533}）也把 supportive 等非矛盾噪音归为「beneficial noise」，本项目的 supportive 条件下 confidence=0.734 高于 naive 的 0.720 印证了这一点。该效应在 $r\geq 0.5$ 后迅速消失，因为 positive 被挤出主导了性能。

\paragraph{成因 4：小样本波动。}
RGB zh/main $n=50$ 上 naive 在 $r=0.5$ 时 F1=0.714，仅高于 clean 0.001，处于噪声带内。$n=50$ 时单样本翻转即可造成约 0.01--0.02 的指标抖动，因此 $\Delta<0.02$ 的「上升」应视为统计噪声而非真实增益。本项目大规模数据集（2Wiki $n=500$、Cmedqa $n=3999$）未观察到此类近零波动，佐证小样本是主因。

\paragraph{统一判断与对结论的影响。}
综合上述四类成因，可得到三条统一规律：（1）「噪音上升反而答对」并非噪音本身有益，而是\textbf{特定任务+特定方法+特定指标}的耦合效应——prompt/voting 需要 negative 作对照、Token-F1 在长答案上失真、低比例噪音提供增广、小样本产生抖动；（2）该现象集中在\textbf{中低噪音比例（$r\leq 0.5$）或 noncalc 这类单事实任务}，$r=0.75$ 以上的强噪音和高计算负担任务（如 MobileMem calc）中 confidence/naive 均单调下降，未出现反向上升，说明互锁效应和「证据定位 vs 矛盾识别」的主结论不受影响；（3）它进一步支持了报告的「指标必须按数据集解释」与「任务类型会改变最优方法」两条结论，而非与之矛盾。因此在阅读后续表格时，对 $\Delta S < 0.02$ 或长答案 Token-F1 的「上升」应结合 Judge Score 与样例交叉验证，避免把指标口径效应误读为方法增益。

\textbf{创新点总结：}
\begin{enumerate}
  \item 发现了“互锁效应”——最优矫正方法取决于噪音类型，confidence（CoT 证据链）在语义噪音下通常有效，但在反事实噪音下可能有害；
  \item 提出并验证了自适应矫正器，利用噪音类型检测实现方法路由；
  \item 提出语义级 ISR/NAR，将 token 重叠升级为 LLM 驱动的信息归属判定；
  \item 发现了在高强度反事实噪音下的位置效应，back 位置最差，interleave 最优；
  \item 提供了 RGB、2Wiki、Cmedqa、MIRIAD、MobileMem、BRIGHT、TEMPO、MultiHop-RAG、NoiserBench 的多数据集 RAG 鲁棒性评测；
  \item 构建了 MobileMem 私人记忆 RAG benchmark，用于评估个人助手场景中的高相关语义噪音。
\end{enumerate}



\subsection{方法边界与不足}
\begin{itemize}
  \item $r=1.0$ 时 positive 消失，矫正多数失效；
  \item counterfactual 噪音下 confidence 可能强化假证据，需 adaptive/prompt；
  \item 跨数据集指标口径不同，Token-F1 与 Judge Score 需分别解释；
  \item 依赖 4B 本地模型与 Judge 主观性；长答案和医学答案仍需人工抽样复核；
  \item BRIGHT 等长文数据需 prompt 截断；TEMPO、MultiHop-RAG、NoiserBench 为 $n=50$ 批量验证，MIRIAD 为 $n=100$ 医学对照，后续可继续扩大样本量。
  \item 「噪音上升反而答对」现象（见第~\ref{sec:noise_up_acc_up} 节）在 33 处样本中出现，主要来自强约束提示需要 negative 作对照、Token-F1 在长答案上失真、低比例噪音的上下文增广以及小样本波动；其存在于中低噪音比例或单事实任务，不影响「证据定位 vs 矛盾识别」的互锁主结论，但提醒阅读时对 $\Delta S<0.02$ 或长答案字面指标应结合 Judge 与样例交叉验证。
\end{itemize}
